## 各章で広げる内容と完了条件

### 第3章: 目的から回路を組み立てる

最初の節を、コンストラクタとメソッドの紹介から、測りたい対象に合わせて量子ビット・古典ビット・測定先を決める説明へ広げる。続いて回路の合成、逆操作、制御操作、パラメータの束縛へ進む。量子回路内の測定結果による条件分岐と、Pythonの`if`の役割の違いを、実行される時点と使う値から説明する。

- [ ] 目的、必要なレジスタ、操作、測定先、出力を一つの例で追える。
- [ ] `compose`と`append`などの選択理由を説明し、量子ビットの対応を変えた例も示す。
- [ ] 固定値の回路からパラメータ付き回路へ進み、複数条件を試す動機を示す。
- [ ] 読者が別の測定先や条件で回路を組む確認問題と、理由付き解答を付ける。

### 第4章: 実行先の制約と変換を理解する

実機ではなぜ元の回路をそのまま実行できるとは限らないのかを、利用できるゲート、量子ビット間の接続、論理量子ビットと物理量子ビットの対応から説明する。変換前後の回路図とlayoutを照合できるローカルの例を置く。その後に実機への送信とJob・Session・Batchの使い分けをつなぐ。

- [ ] 認証なしの例で、変換前後の回路とlayoutが表す対応を確認できる。
- [ ] 測定したい演算子にもlayoutを反映する理由を、第6章への前提として説明する。
- [ ] 一回の実行、結果を使って次を決める実行、独立した複数実行の例から実行モードを選べる。
- [ ] パッケージのAPIと、サービス・実行先の条件を分けて記述する。

### 第5章: サンプルから測定結果を読む

理論上の確率と有限回数の測定結果の違いを第2章から引き継ぎ、各shotの記録がcountsになる過程を示す。PUB、パラメータの軸、shotsの指定位置と優先順位、古典レジスタごとの結果の取り出し方を具体化する。DDは略語と設定値を示す前に、待ち時間中の誤差を抑える目的と仕組みを説明する。

- [ ] 一つの測定記録、counts、相対度数を区別して読める。
- [ ] パラメータ条件を増やした場合の結果の位置と、shotsを指定する場所の違いを追える。
- [ ] 名前を付けた古典レジスタや複数の古典レジスタから結果を取り出す例を含める。
- [ ] ローカルSamplerとRuntime Samplerの生成・設定・実行条件を混同しない。
- [ ] DDの初出説明を整え、第6章の関連説明との重複を調整する。

### 第7章: 結果と不確かさから判断する

jobの状態や結果を取得する操作から、取得した値をどう判断するかへ説明を広げる。PUBごとの結果、パラメータ条件、shotsをそれぞれ区別し、条件ごとのcountsと集約したcountsの意味を示す。統計的な不確かさは式の提示だけで終わらせず、測定回数を変えた具体例と解釈を加える。

- [ ] 結果オブジェクトの階層を、どの入力に対応する値か説明しながらたどれる。
- [ ] `BitArray.get_counts(loc)`で条件を指定する場合と、集約する場合の違いを確認できる。
- [ ] 観測値の変動と、理論値や異なる実行結果との差を慎重に解釈する例を示す。
- [ ] 再現・比較に必要な入力、shots、options、metadataを整理し、第2・5・6章から参照できるようにする。

### 第8章: OpenQASMを状態の変化として読む

型や構文の一覧に加え、短い完結したプログラムを行ごとに読む例を置く。量子状態と古典変数の値の変化を分けて追い、型や条件分岐を選ぶ理由を説明する。文字列とファイルの入出力を区別し、Qiskitとの往復で確認できることと、対応していない構文や機能を整理する。

- [ ] 宣言、ゲート、測定、古典的な処理の役割を一つのプログラムで説明する。
- [ ] `dumps`・`loads`とファイルへの入出力の違いを、実行例で確認できる。
- [ ] importerの依存関係と、往復変換で保持・確認する対象を明示する。
- [ ] 言語仕様上の有効性、SDKの対応、QPU・サービスでの実行可否、REST APIの役割を分ける。

## 一回の改稿の進め方

1. 対象節の到達目標と必要な前提を決め、現在の説明で何が飛んでいるかを挙げる。
2. 前提・例題・コードと出力・条件を変えた確認問題を、一つの学習の流れとして改稿する。
3. 数式を確認し、掲載コードを対象バージョンで実行する。リンク・数式表示・表・図も確認し、検証記録に対象と結果を残す。
4. 読者と、途中計算の量、指示語の明確さ、説明の重複、例から応用へのつながりを確認する。
5. 指摘を反映し、計画の該当項目を更新してから次の節へ進む。

自動検証の通過と、説明の分かりやすさは別々に確認する。未実行の実機例やサービス依存の条件は、ローカル検証の結果で確認済みとは扱わない。
